6) BOOK A SESSION: FULL MECHANISM FOR OWNER
This section is the simple owner workflow for booking.

How it works:
1. Michael adds availability slots in his Google Calendar.
2. Those available slots automatically show on the website booking page.
3. A visitor chooses one slot and books it.
4. The booked session is added to the calendar.
5. The meeting link is created automatically.
6. Michael and the client receive the meeting details by calendar/email.

How Michael should add availability slots:
1. Create a calendar event for the time he is available.
2. Mark it clearly as available using the agreed slot label.
3. Save it in the calendar.
4. The slot will appear on the website for users to book.

Example slot titles:
Example 1:
Availability Session - 60 minutes

Example 2:
Intro Session

Example 3:
Clarity Session - Language and Belief

What Michael does not need to manage manually:
1. No separate booking spreadsheet.
2. No manual meeting link creation.
3. No manual email sending for the meeting link.
4. No manual transfer of the booked slot into another system.

What happens after booking:
1. The session is reserved.
2. The meeting link is created automatically.
3. The calendar entry and email contain the meeting details.
4. The slot is no longer shown as available.


7) WHAT IS CONNECTED TO SANITY VS NOT CONNECTED

7.1 Connected and actively used
1. Hero Section: headline, subheadline, showcasePhotos
2. About Section: portrait, bio, quote, attribution, experience/session/affiliation fields
3. Services
4. YouTube Videos
5. Publications

7.2 Exists in schema/query but not actively used on visible UI right now
1. Hero fields ctaPrimary, ctaPrimaryLink, ctaSecondary, ctaSecondaryLink, backgroundImage, quote, quoteAuthor exist but most are not rendered in the current homepage implementation.
2. Testimonials schema/query exists but no active testimonials section is mounted on pages.
3. Philosophical Quotes schema/query exists but not mounted in current visible page flow.
4. Site Settings schema exists but no active frontend binding currently reads site title/tagline/contact from this document.


8) HARD CODED CONTENT (CODE CHANGES REQUIRED)
These cannot be changed in Sanity currently:

1. Main navigation labels and brand text
2. Footer prompt deck, session compass labels, and footer microcopy
3. Homepage rotating typewriter reflections and large featured quote text
4. Homepage index row labels and descriptions (About/Services/The Practice/Publications/Videos strip)
5. Practice page core text and method cards
6. Contact page option cards and pre-session prep text
7. Most page headers (label, title, subtitle)
8. About lower credential cards content in current design


9) QUICK CHANGE EXAMPLES

Example A: Change homepage H1 "Thinking with Care..."
1. Open /studio
2. Open Hero Section
3. Edit Headline
4. Publish
5. Reload homepage

Example B: Change homepage carousel image titles
1. Open /studio
2. Open Hero Section
3. Edit Home Showcase Photos item title/subtitle/image
4. Publish

Example C: Change About quote
1. Open /studio
2. Open About Section
3. Edit Philosophy Quote and Quote Attribution
4. Publish

Example D: Add a new service
1. Open /studio
2. Open Services
3. Create new item with title/description/price/features/cta/order
4. Publish

Example E: Make a slot available for booking
1. Open configured Google Calendar
2. Create event inside next 45 days
3. Include [AVAILABLE] in event title
4. Keep attendees empty
5. Save
6. Visit /book-session and verify slot appears
